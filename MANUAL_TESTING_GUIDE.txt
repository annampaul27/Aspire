1. LOCAL ENVIRONMENT SETUP & SERVER STARTUP
================================================================================

Make sure you have two terminal windows open:

TERMINAL 1: BACKEND (FastAPI - Port 8000)
----------------------------------------
1. Navigate to the backend directory:
   cd backend
2. Activate Python virtual environment:
   Windows: .\venv\Scripts\activate
   Linux/macOS: source venv/bin/activate
3. Start the FastAPI development server:
   python run.py
4. Verify backend health:
   Open http://localhost:8000/health in browser (Should return: {"status": "healthy"})
   Interactive Swagger docs: http://localhost:8000/docs

TERMINAL 2: FRONTEND (Next.js 15 - Port 3000)
---------------------------------------------
1. Navigate to the frontend directory:
   cd frontend
2. Start the Next.js development server:
   npm run dev
3. Open http://localhost:3000 in your browser.

4. TEST SUITE 2: ISOLATED CODE EXECUTION SANDBOX & ANTI-CHEATING
================================================================================

TEST 2.1: Valid Production Bug-Fix Execution
- URL: http://localhost:3000/student OR http://localhost:3000/demo
- Steps:
  1. In Zone B or the student challenges section, locate the "Interactive Code Bug-Fixer Sandbox".
  2. Look at the default buggy code containing synchronous sleep:
     time.sleep(5)
  3. Replace the sleep call with non-blocking async code:
     await asyncio.sleep(0.01)
  4. Click "Run Tests" or "Evaluate Bug Fix".
- Expected Result:
  Tests pass in <20ms; terminal output shows non-blocking event-loop throughput;
  a green success banner confirms verification gates passed.

TEST 2.2: AST Security Injection Filter (Malicious Code Block)
- Steps:
  1. In the sandbox code editor, insert dangerous Python system commands:
     import os
     os.system("echo hacked")
  2. Click "Run Tests".
- Expected Result:
  The AST Security Analyzer immediately intercepts the code BEFORE execution.
  A red security error is returned: "Forbidden import: os is restricted in isolated sandbox."
  No host process or shell command is executed.

TEST 2.3: Anti-Cheating Comment Bypass Defense
- Steps:
  1. In the database optimization challenge, attempt to spoof passing criteria by writing comments:
     # CREATE INDEX idx_users_email ON users(email);
  2. Click "Run Tests".
- Expected Result:
  The evaluator ignores spoofed comments, parses the genuine AST/DDL syntax,
  and flags that the actual relational index was not created.

TEST 2.4: 50,000-Row Relational Performance Benchmark (EXPLAIN QUERY PLAN)
- Steps:
  1. Open the Database Performance Challenge modal.
  2. Enter the genuine SQL optimization:
     CREATE INDEX idx_users_email ON users(email);
  3. Click "Execute DDL & Benchmark".
- Expected Result:
  The backend spins up an ephemeral 50k-row SQLite instance;
  Telemetry displays real EXPLAIN QUERY PLAN shifting from "SCAN users" to
  "SEARCH users USING INDEX idx_users_email", recording a 99%+ query latency drop.
